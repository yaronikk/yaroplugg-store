# Подключение заказов и Telegram уведомлений

В архиве корзины и оформления заказа не было. Изменения добавляют выбор размера/длины и цвета, корзину и создание заказа со статусом `pending_payment`. Оплата не подключена, а остатки намеренно не списываются и не резервируются.

## 1. Убедитесь, что каталог уже работает в Supabase

Откройте Supabase Dashboard → свой проект → **Table Editor → products**. Эта версия магазина ожидает в `products` поля `id`, `name`, `price`, `stock`, `sizes`, `lengths`, `colors`, `is_active`, `category_id`; таблицу `categories` с `id` и `name`. Проверка наличия и цены использует именно их.

SQL в `database.sql` — устаревшая первоначальная схема из архива и не соответствует текущей админке. Не запускайте её поверх действующего магазина и не меняйте текущие таблицы товаров ради этого шага. Если перечисленных полей нет, остановитесь: сначала нужно сопоставить вашу рабочую схему Supabase.

## 2. Создайте таблицы заказов

1. В Supabase Dashboard откройте **SQL Editor → New query**.
2. Откройте файл `supabase/migrations/202610170001_orders.sql` в редакторе на компьютере.
3. Скопируйте весь файл в SQL Editor и нажмите **Run**.
4. Убедитесь в **Table Editor**, что появились `store_orders` и `store_order_items`.

Публичные роли не имеют доступа к этим таблицам. Заказ создаёт только Edge Function с серверным ключом.

## 3. Подготовьте Telegram бота

1. Откройте **@BotFather** в Telegram и создайте бота либо выберите уже созданного.
2. Скопируйте выданный bot token. Не отправляйте его в чат, GitHub или Vercel и не добавляйте в `VITE_*` переменные.
3. Откройте бота по ссылке BotFather и нажмите **Start** от своего аккаунта.
4. Узнайте свой числовой Telegram ID у **@userinfobot**. Это значение нужно как `TELEGRAM_CHAT_ID`; оно не является секретом.
5. В BotFather откройте **Bot Settings → Menu Button → Configure menu button**, укажите HTTPS адрес опубликованного магазина и название, например `Open store`. Если Mini App уже настроен, оставьте текущую ссылку.

Подпись `initData` проверяется на сервере токеном бота, поэтому заказ разрешён только из Telegram Mini App. Уведомление отправляется только после успешного сохранения нового заказа; повтор запроса с тем же ключом не посылает дубликат.

## 4. Добавьте серверные секреты

1. В Supabase Dashboard откройте **Edge Functions → Secrets** (в некоторых версиях: **Project Settings → Edge Functions → Secrets**).
2. Добавьте `TELEGRAM_BOT_TOKEN` со значением bot token и `TELEGRAM_CHAT_ID` со своим ID.
3. Не создавайте `SUPABASE_SERVICE_ROLE_KEY` вручную, если он уже предоставлен проекту как системный секрет Edge Functions. Никогда не копируйте этот ключ в браузерный код или Vercel `VITE_*`.

Для успешного оформления нужны оба Telegram секрета. Если их нет, функция не создаст заказ.

## 5. Опубликуйте Edge Function

Из терминала в папке `yaroplugg-store-main`:

1. Установите Supabase CLI согласно официальной инструкции Supabase и войдите: `supabase login`.
2. Привяжите папку к нужному проекту: `supabase link --project-ref ВАШ_PROJECT_REF` (Project ref находится в **Project Settings → General**).
3. Опубликуйте функцию: `supabase functions deploy create-order`.

Функция находится в `supabase/functions/create-order/index.ts`. В настройках `create-order` отключите **Verify JWT with legacy secret**: Telegram Mini App передаёт свои проверяемые `initData`, а проверку подписи и цен выполняет сама функция. Не добавляйте токен бота в браузерный код или переменные Vercel.

## 6. Проверьте настройки сайта

1. В Vercel убедитесь, что уже заданы `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` для нужного deployment environment. Секрет бота туда не добавляйте.
2. Запустите новый deployment сайта после публикации файлов. В `index.html` подключён Telegram Web App SDK, а CSP разрешает загрузить его с `telegram.org`.
3. Откройте опубликованный магазин именно через Telegram кнопку Mini App, добавьте товар, выберите доступный размер/длину и цвет, откройте сумку, укажите имя и телефон, нажмите **PLACE ORDER**.
4. В Supabase **Table Editor → store_orders** проверьте статус `pending_payment`, сумму в центах и запись в `store_order_items`. Проверьте Telegram личный чат с ботом.

Если заказ сохранён, но уведомление не пришло, проверьте правильность chat ID, что вы нажимали **Start** у бота, секреты функции и **Edge Functions → Logs**. При сбое Telegram сам заказ остаётся созданным; повторная отправка с тем же ключом не дублирует заказ и уведомление автоматически не повторяется.

## Ограничения первого шага

- Цена, активность товара, остаток и выбранные варианты проверяются по Supabase на сервере; сумма из браузера не используется.
- Остаток проверяется при оформлении, но не блокируется и не уменьшается. До подключения транзакционного резерва два одновременных заказа могут пройти на один и тот же остаток.
- Статус `pending_payment` означает, что заказ записан, но оплаты не было. Не отмечайте такой заказ оплаченным по возврату в приложение.
- Если рабочие поля каталога отличаются от указанного формата, нужна адаптация Edge Function под действующую схему до запуска.
